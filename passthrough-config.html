01 憑證 SecretCluster B · namespace cnpg

其他步驟都依賴這兩個 Secret，必須先建立。

CNPG 不會建立這些 Secret，它只讀取你指定名稱的既有 Secret。 Secret 必須與 Cluster 位於同一個 namespace；所有 Cluster 在同一 namespace 時，兩個 Secret 各只需要一份。

方式 A — 已有憑證檔案

kubectl手動建立
# serverTLSSecret：型別必須是 kubernetes.io/tls，key 為 tls.crt / tls.key
kubectl -n cnpg create secret tls db-wildcard-tls \
  --cert=fullchain.pem \
  --key=privkey.pem

# serverCASecret：Opaque 即可，但 key 名稱必須是 ca.crt
kubectl -n cnpg create secret generic db-wildcard-ca \
  --from-file=ca.crt=chain.pem
注意

--cert 要給 fullchain（leaf + 中繼憑證），只放 leaf 會導致 client 端驗證缺鏈。

方式 B — cert-manager 自動簽發與續期

certificate.yamlcert-manager
apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: db-wildcard
  namespace: cnpg                  # 必須與 Cluster 同 namespace
spec:
  secretName: db-wildcard-tls      # 即 serverTLSSecret 要填的名稱
  dnsNames:
    - "*.db.example.com"
  issuerRef:
    name: internal-ca
    kind: ClusterIssuer
ca.crt 不一定會產生

cert-manager 產生的 Secret 裡有沒有 ca.crt 取決於 issuer：

  • 內部 CA（CA Issuer、Vault 等）— Secret 同時包含 tls.crt / tls.key / ca.crt。 此時 serverTLSSecret 與 serverCASecret 可以都填 db-wildcard-tls。
  • ACME / Let's Encrypt — cert-manager 不會產生 ca.crt（設計上的行為，因為 CA 是公開根憑證）。 此時 serverCASecret 需另外以方式 A 手動建立，內容放該 CA 的中繼與根憑證。
SAN 限制

*.db.example.com 只涵蓋一層 label：對得上 tenant1.db.example.com， 對不上 pooler.tenant1.db.example.com。hostname 命名規則需固定為單層。

02 NGINX Ingress ControllerCluster B

建議為 DB 流量部署獨立實例，與 HTTP ingress 分離。

deployment.yaml（節錄）controller args
spec:
  template:
    spec:
      containers:
        - name: nginx-ingress
          args:
            - -nginx-configmaps=$(POD_NAMESPACE)/nginx-config-db
            - -global-configuration=$(POD_NAMESPACE)/nginx-configuration-db
            - -ingress-class=nginx-db          # 獨立 class，不接手 HTTP ingress
            - -enable-tls-passthrough
            - -tls-passthrough-port=5432       # 不使用預設的 443
service.yaml必須開放該 port
apiVersion: v1
kind: Service
metadata:
  name: nginx-ingress-db
  namespace: nginx-ingress
spec:
  type: LoadBalancer
  selector:
    app: nginx-ingress-db
  ports:
    - name: postgres
      port: 5432
      targetPort: 5432
      protocol: TCP
configmap.yamlreload 行為
apiVersion: v1
kind: ConfigMap
metadata:
  name: nginx-config-db
  namespace: nginx-ingress
data:
  worker-shutdown-timeout: "1h"   # 預設值會在 reload 後中斷長連線
  stream-log-format: '$remote_addr [$time_local] $status
    $bytes_sent/$bytes_received $session_time "$ssl_preread_server_name"'
為什麼要獨立實例

reload 由該 controller 上任何資源變更觸發，不限於 TransportServer。 與 HTTP ingress 共用時，HTTP 的變更頻率會決定資料庫連線的存活時間。 獨立實例後，只有自己建立 pooler 時才會 reload。

03 Cluster 憑證設定Cluster B · 每個 Cluster

直通模式由 PgBouncer 出示憑證，而 Pooler 沿用所屬 Cluster 的 server 憑證。

cluster.yaml（節錄）CNPG
apiVersion: postgresql.cnpg.io/v1
kind: Cluster
metadata:
  name: tenant1-db
  namespace: cnpg
spec:
  certificates:
    serverTLSSecret: db-wildcard-tls   # 步驟 1 建立
    serverCASecret:  db-wildcard-ca    # 步驟 1 建立

# 每個 Cluster 填相同的兩個名稱即可，Secret 本身不需要複製。
# client 與 replication 憑證仍由 operator 自行管理，不需變更。
套用順序

Secret 必須先存在，否則套用 Cluster 後 operator 會停在等待狀態。

憑證輪替

cert-manager 更新 Secret 後，CNPG 是否觸發 PgBouncer 重載憑證，文件未明確說明。 在續期流程後加入一次 Pooler rollout，並對憑證到期日設定告警。

04 PoolerCluster B · 每個 pooler

直通模式下 TLS 握手與 ALPN 由 PgBouncer 負責，需 1.25 以上。

pooler.yamlCNPG
apiVersion: postgresql.cnpg.io/v1
kind: Pooler
metadata:
  name: tenant1-pooler              # Service 會使用相同名稱
  namespace: cnpg
spec:
  cluster:
    name: tenant1-db
  instances: 3
  type: rw
  pgbouncer:
    poolMode: transaction
    parameters:
      client_tls_sslmode: "require"
      max_client_conn: "1000"
      default_pool_size: "25"
      max_db_connections: "80"
      ignore_startup_parameters: "extra_float_digits,options"

      # 跨叢集長連線：讓失效的 TCP session 被回收
      tcp_keepalive: "1"
      tcp_keepidle: "30"
      tcp_keepintvl: "10"
      tcp_keepcnt: "3"
      client_idle_timeout: "0"        # 交由 nginx / LB 控制，避免兩邊互踢
      server_idle_timeout: "600"
      server_lifetime: "3600"
      query_wait_timeout: "120"

      log_connections: "1"
      log_disconnections: "1"
  serviceTemplate:
    spec:
      type: ClusterIP               # 不需要 NodePort / LoadBalancer
連線數上限

instances × max_client_conn 決定邊界需維持的並發 TCP session； instances × default_pool_size × (db, user) 組合數 必須小於 PostgreSQL 的 max_connections 減去保留連線。以 max_db_connections 設硬上限。

operator 管理的項目

[databases]、[users] 以及所有 *_tls_*_file 由 operator 管理， 寫入會被忽略或被 webhook 拒絕。可設定的參數為白名單，以所使用的 CNPG 版本文件為準。

05 TransportServerCluster B · 每個 pooler

新增 pooler 時唯一需要重複建立的資源。

transportserver.yamlNGINX IC
apiVersion: k8s.nginx.org/v1
kind: TransportServer
metadata:
  name: tenant1-pg
  namespace: cnpg
spec:
  listener:
    name: tls-passthrough          # 內建 listener，不需在 GlobalConfiguration 宣告
    protocol: TLS_PASSTHROUGH
  host: tenant1.db.example.com   # SNI 比對值
  upstream:
    name: tenant1-pooler
    service: tenant1-pooler        # 步驟 4 的 Pooler 同名 Service
    port: 5432
    maxFails: 2
    failTimeout: 10s
  upstreamParameters:
    connectTimeout: 5s
    nextUpstreamTimeout: 10s
  sessionParameters:
    timeout: 60m                 # 預設 10m
  action:
    pass: tenant1-pooler
唯一性

(listener, host) 的組合必須全域唯一，重複時其中一份 CR 會被拒絕， 且不一定有明顯的錯誤回饋。hostname 建議由 controller 或 template 從 Pooler 名稱推導，不由人工填寫。

06 nginx streamCluster A

不解析、不分流，所有租戶轉往同一個 Cluster B 入口。新增 pooler 時不需變更。

/etc/nginx/nginx.confCluster A
# stream 與 http 同層，不在 http 區塊內
stream {
    log_format pg '$remote_addr [$time_local] $status '
                  '$bytes_sent/$bytes_received $session_time';
    access_log /var/log/nginx/pg.log pg;

    upstream cluster_b_edge {
        # 列出 Cluster B 的 ingress 節點或 LB VIP
        server 10.20.0.11:5432 max_fails=3 fail_timeout=10s;
        server 10.20.0.12:5432 max_fails=3 fail_timeout=10s;
    }

    server {
        listen 5432;
        proxy_pass cluster_b_edge;

        proxy_connect_timeout   5s;
        proxy_timeout           1h;   # 預設 10m
        proxy_socket_keepalive  on;

        # 不要啟用 proxy_protocol：PgBouncer 不支援
    }
}
DNS

一筆 *.db.example.com 指向此 nginx 的 VIP 即可。 新增 pooler 不需要新增 DNS 記錄。

07 Client 連線字串Client

直通模式下 client 必須使用 direct TLS。

連線字串libpq ≥ 17
host=tenant1.db.example.com
port=5432
dbname=app
user=app
sslmode=verify-full
sslnegotiation=direct              # 必要：首包直接送 ClientHello
sslrootcert=/etc/ssl/certs/ca.crt   # 公開 CA 簽發時可省略
keepalives=1
keepalives_idle=30
keepalives_interval=10
URI 形式同上
postgresql://app@tenant1.db.example.com:5432/app\
?sslmode=verify-full\
&sslnegotiation=direct\
&keepalives=1&keepalives_idle=30&keepalives_interval=10
Driver 支援

libpq 17+、pgx v5、node-postgres 已支援 sslnegotiation=direct； Rust 的 sqlx 目前未支援；pgjdbc、asyncpg 需依版本確認。 不支援的 client 得到的錯誤是 server closed the connection unexpectedly，訊息不指向 TLS 交涉方式。

版本相依：direct TLS 需 PostgreSQL 17+ 的 libpq 與 PgBouncer 1.25+ （CNPG 1.26 / 1.27 起新建 Pooler 預設 1.25.1，既有 Pooler 不會自動升級）。
